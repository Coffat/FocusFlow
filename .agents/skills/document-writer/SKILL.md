# PROJECT DOCUMENT STYLE REFERENCE

## 1. REFERENCE DOCUMENT FAMILY

The project documentation follows a formal Software Engineering / Project Management documentation style.

Reference document types include:

- Project Charter
- Statement of Work (SOW)
- Project Status Report
- Requirements Specification
- System Analysis
- System Architecture
- Database Design
- UI/UX Design
- Testing Documentation
- Deployment Documentation

All documents should look like they belong to the same project.

---

# 2. REFERENCE TITLE STYLE

Main title:

PROJECT DOCUMENT NAME

(VIETNAMESE DOCUMENT NAME)

Characteristics:

- uppercase
- centered
- formal
- no decorative subtitle
- no marketing slogan

Example:

PROJECT STATUS REPORT

(BÁO CÁO TÌNH TRẠNG DỰ ÁN)

---

# 3. REFERENCE METADATA STYLE

Metadata appears directly below the title.

Examples:

Dự Án: [Tên Dự Án]

Kỳ Báo Cáo: [Ví dụ: Tuần 4 - Từ ngày ... đến ngày ...]

Người Lập Báo Cáo: [Tên Project Manager]

Gửi Đến: [Giảng viên Hướng dẫn / Ban Lãnh đạo / Khách hàng]

Ngày Gửi: [dd/mm/yyyy]

For project charter:

Mã Dự Án: [Mã Lớp/Mã Nhóm]

Tên Dự Án: [Tên Hệ Thống/Giải Pháp]

Ngày Hiệu Lực: [Ngày/Tháng/Năm]

Phiên Bản: 1.0

---

# 4. REFERENCE HEADING HIERARCHY

Level 1:

1. TỔNG QUAN DỰ ÁN (PROJECT OVERVIEW)

Level 2:

1.1. Mục Tiêu Dự Án (Project Objectives)

Level 3:

1.1.1. ...

The numbering must remain sequential.

---

# 5. REFERENCE CONTENT STYLE

Use formal explanatory paragraphs followed by structured lists or tables.

Example:

"Dựa trên yêu cầu của các bên liên quan, Dự án bao gồm các hạng mục công việc sau:"

Then use:

1. ...
2. ...
3. ...

Do not convert every piece of information into paragraphs.

---

# 6. REFERENCE TABLE STYLE

Tables are an important component of the project documentation style.

Typical examples:

## Milestones

| ID | Giai Đoạn (Phase) | Mốc Sự Kiện (Milestone Event) | Sản Phẩm Bàn Giao (Deliverables) | Thời Hạn (Deadline) |
|---|---|---|---|---|

## Roles

| Vai Trò (Role) | Thành Viên (Resource) | Trách Nhiệm Chính (Key Responsibilities) |
|---|---|---|

## Project Status

| Hạng mục | Trạng thái | Diễn giải ngắn gọn |
|---|---|---|

## Tasks

| ID | Công việc / Hạng mục | Người phụ trách | Kết quả | Ghi chú |
|---|---|---|---|---|

## Risks / Issues

| Loại (Type) | Mô tả vấn đề / Rủi ro | Mức độ tác động | Kế hoạch giải quyết (Action Plan) | Người xử lý | Trạng thái |
|---|---|---|---|---|---|

# 8. REFERENCE RAG STATUS

Green:

🟢 Green

Stable / On-track

Amber:

🟡 Amber

Potential risk / Minor delay

Red:

🔴 Red

Critical issue / Requires intervention

Always explain the status.

---

# 9. REFERENCE PLACEHOLDER STYLE

Unknown project information should be represented as:

[Tên Dự Án]

[Tên Thành Viên]

[Ngày]

[dd/mm/yyyy]

[Mã Dự Án]

[Số]

[Chưa xác định]

[To be confirmed]

Never replace an unknown value with a fabricated value.

---

# 10. DOCUMENT FAMILY RULE

Every document should visually and structurally feel like it belongs to the same project.

Maintain:

- same terminology
- same numbering philosophy
- same bilingual style
- same table philosophy
- same formal tone
- same placeholder convention
- same level of detail

Do not make one document highly decorative while another is formal and plain.

The documentation set must feel professionally standardized.
